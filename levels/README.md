# Уровни Sokoban

Все 101 карта лежат по одной в XSB-файле и сначала сгруппированы по происхождению: [`custom`](library/custom) и [`XSokoban`](library/XSokoban). Внутри каждой группы находятся ручные категории `easy`, `medium`, `hard` и `very-hard`. Родительский `author.json` задаёт автора, а папка сложности — отображаемую сложность уровня.

Сборщик сам обнаруживает группы внутри `library`. Для добавления другого автора создайте новую папку с `author.json` и четырьмя стандартными подпапками сложности; менять список авторов в коде не требуется.

У каждого источника собственное пространство постоянных ID: `custom-001…` и `xSokoban-001…`. Новые карты получают следующий свободный ID своего автора, а существующие карты после удаления соседних не перенумеровываются.

[`locations.json`](locations.json) задаёт 16 игровых локаций, их карточки, фон, звук и порядок карт внутри каждой главы. Чтобы перенести уровень или изменить порядок кнопок слева направо, достаточно переставить его `id` в массивах `levelIds`. Включённый в игру `id` должен встречаться ровно один раз. Карты без назначения остаются в библиотеке и не попадают в `generated`.

Во вкладке «Автогенерация» кнопка «Сохранить как» создаёт новый XSB в выбранной существующей коллекции и разделе сложности. Имя без расширения становится уникальным `id` во всей библиотеке; занятое имя нужно изменить. Сохранённый файл становится текущим, обычная кнопка сохранения обновляет его, а список «Библиотека — уровни вне игры» позволяет открыть его повторно. «Черновик» запускает его карту на основе доступной игровой локации, не меняя исходники игры.

Оформление самостоятельной карты хранится в необязательной строке `; appearance: {...}`: это JSON со слоями `wall`, `decor`, `ground`, `box`, `target`, координатами `x:y` и именами текстур. Стандартные XSB-редакторы воспринимают эту строку как комментарий. При добавлении `id` в локацию сборщик использует это оформление, если для уровня ещё нет записи в `levels/appearance/<location-id>.json`. Сохранение через редактор игровой локации переносит актуальное оформление в её JSON и удаляет прежнюю строку из XSB.

Оформление также разделено по локациям в папке [`appearance`](appearance). После переноса карты старое оформление игнорируется, а новое можно быстро назначить заливкой в редакторе. Игровые JSON в `src/game/generatedAssets/levels` создаются автоматически и вручную не редактируются.

Общая справка: [`docs/levels/overview.md`](../docs/levels/overview.md).

Дорожные карты:

- [добавление уровня в существующую карточку](../docs/levels/add-level-to-existing-card.md);
- [создание карточки локации и добавление в главы](../docs/levels/create-location-card.md).

В `locations.json` каждый идентификатор в `levelIds` записывается с новой строки. Правило `json-stringify` в корневом `.prettierrc` сохраняет этот вид при форматировании.

Основные команды:

```bash
npm run levels
npm run levels:check
```

`npm start` и `npm run build` обновляют игровые JSON автоматически. Результаты решателей в каталоге не хранятся: игрок сравнивает прохождения только со своим личным рекордом.
