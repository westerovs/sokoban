| Команда | Что делает |
| --- | --- |
| `npm start` | Сначала выполняет общую команду `prepare`, затем запускает Vite-сервер разработки для платформы по умолчанию. Во время работы Vite отслеживает изменения исходного кода и `raw-assets`; редактор уровней доступен из debug-интерфейса игры. Другую платформу можно выбрать через Vite mode, например `npm start -- --mode dev` или `npm start -- --mode playgama`. |
| `npm run build` | Сначала выполняет общую команду `prepare`, затем создаёт production-сборки платформ через Vite. Без аргументов собирает платформы из `PLATFORMS_TO_BUILD`; конкретные платформы можно передать после `--`, например `npm run build -- yandex playgama`, а `npm run build -- all` собирает все production-платформы. Перед сборкой очищает `dist`, платформы собирает параллельно, а результат каждой помещает в отдельную папку внутри `dist` вместе с нужными ассетами. |
| `npm run prepare` | Выполняет общую подготовку проекта: последовательно запускает `levels`, `assets` и `generate_game_meta`. Команда обновляет игровые уровни и ресурсы, затем создаёт актуальные метаданные сборки, список звуков и каталог тайлов Sokoban. `start` и `build` вызывают её автоматически; npm также может выполнять специальный lifecycle-скрипт `prepare` при установке зависимостей и упаковке проекта. |
| `npm run assets` | Обрабатывает исходные ресурсы из `raw-assets` через AssetPack по конфигурации `.assetpack.mjs` и создаёт игровые ресурсы в `public/assets`. Проверяет служебный кэш `.assetpack`, удаляет его при обнаружении незавершённой сборки и сохраняет маркер только после успешного завершения. |
| `npm run generate_game_meta` | Обновляет генерируемые данные проекта: метаданные сборки, список звуков и каталог тайлов Sokoban. Команда входит в общую подготовку `prepare`; вручную нужна только для отдельного обновления этих файлов. |
| `npm run levels` | Читает карты из `levels/maps`, настройки локаций из `levels/locations.json`, оформление из `levels/appearance` и статистику решателя. Проверяет структуру карт, уникальность идентификаторов, соответствие ящиков целям, допустимые размеры, привязку уровней к локациям, оформление и сохранённые решения. После проверки создаёт игровые JSON-файлы локаций в `src/game/gameConfig/levels/generated` и обновляет индекс `src/game/gameConfig/levels/levels.ts`; устаревшие сгенерированные файлы удаляет. |
| `npm run levels:check` | Выполняет те же проверки уровней, что и `npm run levels`, но работает в режиме контроля: не изменяет файлы и завершает процесс с ошибкой, если сгенерированные данные отсутствуют, устарели или должны быть удалены. Подходит для CI и проверки репозитория перед коммитом. |
| `npm run typecheck` | Запускает TypeScript с параметром `--noEmit`: проверяет типы по `tsconfig.json`, но не создаёт JavaScript-файлы и не изменяет исходники. |
| `npm run eslint` | Проверяет файлы в `src` правилами ESLint и сообщает о найденных ошибках, ничего автоматически не исправляя. |
| `npm run eslint:fix` | Проверяет файлы в `src` правилами ESLint и автоматически исправляет те нарушения, для которых ESLint поддерживает безопасное исправление; остальные ошибки выводит в консоль. |
| `npm run prettier` | Проверяет форматирование файлов в `src` по настройкам Prettier, не изменяя их. Завершается с ошибкой, если обнаруживает файлы с неподходящим форматированием. |
| `npm run prettier:fix` | Форматирует файлы в `src` по настройкам Prettier и записывает изменения на диск. |
