----- Добавление новой платформы под сборку ----

1) Создать директорию платформы в `services/`.
2) Настроить файлы платформы:
   - `Service.js` — подключить нужный адаптер и создать игру;
   - `index.html` — добавить SDK, метаданные и разметку, которые требует площадка.
3) Зарегистрировать платформу в `bundler/platformConfig.mjs`: указать имя для команд, директорию в `services/` и имя выходной папки платформы.
4) Если платформа должна собираться командой `npm run build` без аргументов, добавить её в массив `PLATFORMS_TO_BUILD`.

Отдельный конфиг сборщика платформе не нужен. Vite собирает только выбранную точку входа, поэтому адаптеры остальных площадок не попадают в итоговый bundle.

-------- Добавление ассетов и их сборка --------

Исходники всех игровых ресурсов находятся в `raw-assets`. Папка `public/assets` создаётся AssetPack автоматически, не хранится в Git и вручную не редактируется.

Ресурсы, которые должны копироваться без преобразований, помечены суффиксом `{copy}`. Например, `audio{copy}` на выходе становится `public/assets/audio`. Каталоги и другие вспомогательные исходники, которые не должны попадать в игру, помечаются `{ignore}`.

UI-атласы находятся в `raw-assets/ui`. Каждая папка одного атласа имеет суффиксы `{m}{tps}`:

- `{tps}` собирает все изображения папки и её подпапок в spritesheet;
- `{m}` добавляет атлас в manifest AssetPack;
- имя папки без суффиксов становится именем готового атласа.

Например, изображения из `raw-assets/ui/startScreenUi{m}{tps}` превращаются в `startScreenUi@2x.png`, `startScreenUi@2x.png.json` и WebP-варианты. Дополнительно AssetPack создаёт обычную 1x-версию. Игра загружает `@2x`, поэтому существующие размеры и retina-масштаб UI сохраняются.

`startScreenUi` содержит элементы первого экрана, а `levelUi` — элементы, загружаемые при переходе к уровню. Для отдельной группы загрузки нужно создать рядом новую папку вида `имяАтласа{m}{tps}`.

Конфигурация находится в `.assetpack.mjs`. После упаковки PNG-атласы дополнительно сжимаются через Tinify.

Запустить только обработку ресурсов:

```bash
npm run assets
```

Команды `npm run dev` и `npm run build` выполняют AssetPack автоматически. Во время работы Vite изменения в `raw-assets` отслеживаются, поэтому после добавления или замены изображения атлас пересобирается без перезапуска dev-сервера.


---------------- Тестирование ------------------
Ссылка на remote/local тестирование хранятся в файле getAssetsUrl
Для тестирования можно использовать github, куда необходимо залить свои ассеты.
Поменять константу GIT_PATH по необходимости. Это адрес репозитория.
Для тестирования из репозитория гитхаба нужно в файле constants раскомментировать: 
const ASSETS_URL = URL_PRESET.GIT_TEST

Запуск с платформой по умолчанию:

```bash
npm run dev
```

Платформа по умолчанию задаётся в `bundler/platformConfig.mjs` константой `DEFAULT_DEV_PLATFORM`. Для разового запуска менять конфиг не нужно — передайте имя платформы через Vite mode:

```bash
npm run dev -- --mode dev
npm run dev -- --mode playgama
```

`noAdapter` используется для обычной локальной разработки и тестирования с телефона. `dev` запускает локальный сценарий Яндекс Игр по HTTPS. Аналогично можно указать любую платформу, зарегистрированную в `bundler/platformConfig.mjs`.

Vite выводит в консоль локальный и сетевой адреса. По сетевому адресу игру можно открыть на телефоне, если телефон и компьютер находятся в одной сети. Изменения исходного кода автоматически применяются dev-сервером.

Для Яндекс Игр используйте режим `dev`:

```bash
npm run dev -- --mode dev
```

Локальный HTTPS-сертификат генерируется автоматически. При первом запуске браузер может показать предупреждение — его нужно разрешить. После этого откройте URL черновика, подставив актуальный id приложения:

`https://yandex.ru/games/app/393972?draft=true&lang=ru&game_url=https://localhost:8080/`

Ссылка локальная и не предназначена для передачи другим пользователям.



------------------ Сборка ----------------------

Сборка платформ, включённых в `PLATFORMS_TO_BUILD` внутри `bundler/platformConfig.mjs`:

```bash
npm run build
```

Одну или несколько платформ можно указать прямо в команде. Выбранные платформы собираются параллельно:

```bash
npm run build -- yandex
npm run build -- yandex playgama youtube
npm run build -- all
```

Перед сборкой автоматически обновляются атласы и метаданные игры. Запускать dev-сервер или отдельно создавать `dist` не нужно.

Результат каждой платформы находится в собственной директории внутри `dist`.
Суффикс папки автоматически берётся из части поля `name` в `package.json` после последней точки:
для `hog.test` папка платформы Yandex называется `YANDEX_test`.

```text
dist/
└── YANDEX_test/
    ├── index.html
    ├── index-a1b2c3d4.js
    └── assets/
```

Хеш в имени JS-файла меняется вместе с содержимым сборки. Архивы больше не создаются: папка платформы уже является готовой сборкой для загрузки на площадку.

Production-сборка ориентирована на современные браузеры с поддержкой ES2020. Legacy-polyfills из старой Babel-конфигурации больше не добавляются.

Для платформ с разделением локальных и удалённых ресурсов рядом с `assets/` также создаётся `remote-assets/`.

Для YouTube может использоваться специальный `youtube-logo.png`. Список игр с таким логотипом задаётся в `gamePreload/preloadList`, а заголовок страницы — в `services/youtube/index.html`.

`LocalPlaygamaAdapter` уже содержит Playgama Bridge, поэтому отдельный `playgama-bridge.js` копировать в сборку не нужно.
