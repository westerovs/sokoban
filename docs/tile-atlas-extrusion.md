# Защита тайлов от швов при масштабировании

## Проверенное сочетание настроек

По результатам визуального сравнения в игре рабочее решение — PNG вместе
с extrude толщиной 1 пиксель и `padding: 2`. После отключения extrude при
сохранении PNG швы вернулись. Поэтому рамка остаётся включённой: PNG
устраняет цветовые искажения сжатия WebP, а extrude защищает выборку на
границе кадра от прозрачных пикселей атласа.

## Формат загрузки

Игра и редактор загружают атлас `tiles` из PNG. Игра сохраняет выбор
разрешения 1x/2x через `LoadUtils`, редактор использует путь PNG из каталога
тайлов. Выбор формата остальных атласов не изменён.

Причина: сжатие WebP с потерями меняет RGB на краях даже полностью
непрозрачного однотонного `ground4`, включая добавленную рамку. Проверки
одной альфы недостаточно. Переключение на PNG позволяет сравнить ту же сцену
без этих цветовых искажений. WebP продолжает генерироваться, но для тайлов
не выбирается загрузчиками.

## Почему появляются полосы

При линейной фильтрации PixiJS выборка на границе кадра может захватывать
прозрачные пиксели за его пределами в атласе. В результате фон проступает
между соседними тайлами, даже если исходник полностью непрозрачен и спрайты
стоят вплотную. Это воспроизводилось на однотонном тестовом `ground4.png`.

`padding` задаёт свободное расстояние между кадрами. Увеличение прозрачного
отступа защищает от подмешивания соседних изображений, но само по себе
не устраняет подмешивание прозрачности.

## Как устроено исправление

В `.assetpack.mjs` стандартный `texture-packer` дополняется обработчиком
`bundler/utils/extrudeTileAtlas.mjs`. Он обрабатывает только исходную папку
атласа `tiles{m}{tps}`. Остальные атласы проходят обычную упаковку.

Сразу после упаковки, до сжатия PNG/WebP, вокруг каждого кадра создаётся
рамка толщиной один физический пиксель — extrude:

- строки сверху и снизу копируются из ближайшей строки кадра;
- столбцы слева и справа копируются из ближайшего столбца кадра;
- углы копируются из соответствующих углов кадра;
- копируются все каналы RGBA, включая исходную прозрачность.

Рамка находится за пределами кадра. JSON, координаты, размеры, обрезка и
содержимое кадров не изменяются. Поворот при упаковке учитывается при
определении фактического прямоугольника изображения в атласе.

Каждая страница каждого разрешения обрабатывается отдельно: у вариантов
1x и 2x рамка имеет одинаковую толщину в физических пикселях. Затем штатные
пайпы AssetPack создают PNG/WebP. Результаты размещаются в
`public/assets/ui/tiles/` существующим обработчиком `atlasFolders`.

Палитровое сжатие PNG и сжатие WebP могут немного изменить цвета после
копирования. Побайтовое равенство рамки краю проверяется до сжатия; в готовых
файлах дополнительно проверяется непрозрачность рамки тестового `ground4`.

## Ограничения настроек

- `EXTRUDE_SIZE` в обработчике сейчас равен `1`.
- `texturePacker.padding` должен быть не меньше `2 * EXTRUDE_SIZE`:
  при толщине `1` нужен отступ минимум `2`, по пикселю для каждого соседа.
- По внешнему краю атласа должно оставаться место для рамки.
- Обработчик завершает сборку с ошибкой при недостаточном отступе.
- Изменение толщины требует пересборки всех разрешений атласа.

Не нужно расширять спрайты, менять размер клетки или включать `nearest`
глобально. Рамка не делает полупрозрачные исходники непрозрачными и не
исправляет реальные геометрические зазоры между спрайтами.

## Пересборка и проверка

Обычная сборка: `npm run assets`.

Толщина рамки включена в ключ кэша упаковщика: подключение обработчика и
изменение `EXTRUDE_SIZE` автоматически приводят к пересборке.

После изменения самого обработчика нельзя полагаться на старый кэш:
AssetPack может не заметить изменение реализации функции. Для принудительной
сборки без использования кэша из корня проекта выполните:

```sh
node --import tsx --input-type=module -e "import {AssetPack} from '@assetpack/core'; import config from './.assetpack.mjs'; const pack = new AssetPack({...config, cache: false}); await pack.run();"
```

Команда пересоздаёт генерируемые ресурсы в `public/assets`; исходники не
меняются. Последующий `npm run prepare` восстанавливает обычный кэш и
генерирует метаданные для запуска игры.

Проверка результата:

1. У кадра `ground4` внешняя рамка должна быть розовой с альфой 255.
2. Размеры и координаты кадров должны совпадать с упаковкой без extrude.
3. Проверить PNG/WebP, версии 1x/2x и повёрнутые прямоугольные кадры.
4. Перезагрузить игру без браузерного кэша; проверить пол и кусты при зуме
   и изменении размера окна. Если полосы сохраняются, отдельно исследовать
   экранные границы спрайтов и используемый браузером атлас.

Настройки других атласов для исправления швов тайлов менять не требуется.
