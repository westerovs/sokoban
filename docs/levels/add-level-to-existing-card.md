# Дорожная карта: добавить уровень в существующую карточку

Эта инструкция подходит, когда новая карта должна появиться внутри уже существующей локации. Создавать новую карточку, название, фон или музыку в этом сценарии не требуется.

## Результат

После выполнения дорожной карты:

- карта хранится в `levels/maps/<location-id>.xsb`;
- её постоянный идентификатор добавлен в одну существующую локацию;
- игровой JSON выбранной локации пересобран;
- карта доступна на экране выбора уровней внутри нужной карточки;
- проходимость подтверждена решателем.

## Этап 1. Выбрать локацию и позицию уровня

1. Откройте `levels/locations.json`.
2. Найдите карточку по её постоянному `id`, например `garden-1`.
3. Определите позицию нового уровня в массиве `levelIds`.

Позиция идентификатора в `levelIds` задаёт номер кнопки внутри карточки. Все уровни открытой локации доступны сразу, поэтому этот порядок отвечает за отображение, а не за последовательную разблокировку карт.

## Этап 2. Добавить карту в XSB

1. Откройте XSB выбранной локации, например `levels/maps/garden-1.xsb`.
2. Добавьте новую карту в позицию, соответствующую её месту в `levelIds`.
3. Отделите карту от предыдущей одной пустой строкой.
4. Добавьте новый уникальный постоянный идентификатор, например:

```text
; id: sokoban-102
```

5. Ниже вставьте геометрию карты в стандартном XSB-формате.

Символы формата, пример и ограничения карты собраны в общей справке: [«Что такое XSB»](overview.md#что-такое-xsb) и [«Требования к карте»](overview.md#требования-к-карте).

## Этап 3. Привязать уровень к карточке

Добавьте новый `id` в `levelIds` выбранной записи `levels/locations.json`:

```json
{
  "id": "garden-1",
  "levelIds": ["sokoban-001", "sokoban-102", "sokoban-002"]
}
```

В реальном файле сохраните остальные поля локации. Каждый идентификатор из `levels/maps/*.xsb` обязан встречаться ровно в одном массиве `levelIds`: пропуск и повторное назначение остановят генерацию.

## Этап 4. Пересобрать игровой каталог

Запустите:

```bash
npm run levels
npm run levels:check
```

Первая команда проверит XSB и обновит JSON в `src/game/gameConfig/levels/generated`. Вторая подтвердит, что сгенерированные файлы актуальны. Не редактируйте их вручную.

Если для изменённого уровня уже существовала запись в `levels/metadata/solver-stats.json`, старый хеш и решение станут недействительными. Удалите устаревшую запись и добавляйте новую статистику только после повторной проверки решателем.

## Этап 5. Проверить карту в игре

Запустите игру и проверьте:

1. карточка показывает новое общее количество уровней;
2. кнопка нового уровня находится на выбранной позиции;
3. предпросмотр карты отображается корректно;
4. работают перемещение, отмена хода и рестарт;
5. уровень завершается после установки всех ящиков на цели;
6. завершение корректно обновляет прогресс карточки;
7. кнопка «Продолжить» ведёт к ожидаемой карте.

## Этап 6. Подтвердить проходимость

1. Откройте XSB выбранной локации в JSoko или другом решателе.
2. Выберите добавленную карту.
3. Найдите хотя бы одно решение в режиме `Any solution`.
4. Сохраните LURD-строку, количество ходов и толчков, название и версию решателя.
5. При необходимости обновите `levels/metadata/solver-stats.json` проверенными данными.

Настройка JSoko, значение LURD и состав сохраняемого результата описаны в разделах [«Рекомендуемый решатель: JSoko»](overview.md#рекомендуемый-решатель-jsoko) и [«Что передать после проверки»](overview.md#что-передать-после-проверки).

## Готово, когда

- новый `id` уникален;
- карта находится только в XSB выбранной локации;
- `id` указан ровно в одной карточке;
- `npm run levels:check` проходит;
- карта пройдена в игре;
- решение подтверждено решателем;
- `npm run typecheck` и `npm run build` проходят.
