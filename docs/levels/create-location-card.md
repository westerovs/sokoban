# Дорожная карта: создать карточку локации и добавить её в главы

Эта инструкция подходит, когда группе уровней нужна отдельная карточка со своим названием, изображением, фоном и звуком.

В коде одна карточка соответствует одной **локации**. Пользовательский порядок глав совпадает с порядком объектов в массиве `locations` файла `levels/locations.json`.

Общая модель иерархии, разблокировки и сохранения прогресса описана в разделе [«Локации и карточки»](overview.md#локации-и-карточки). Отдельной конфигурации глав нет: экран делит массив `locations` на страницы по четыре карточки, а позиция объекта задаёт номер главы и цепочку разблокировки.

## Этап 1. Спроектировать карточку

До изменения файлов определите:

- постоянный `id` локации, например `harbor-1`;
- позицию в общей последовательности глав;
- ключ локализации, например `locations.harbor`;
- alias изображения карточки, например `card-harbor`;
- имя фоновой текстуры, например `harbor`;
- ambience, например `amb_harbor`;
- музыкальный трек, например `m_harbor`;
- список уровней и их порядок.

Не переименовывайте `id` уже выпущенной локации: он хранится в прогрессе игрока. Вставка новой карточки в середину меняет цепочку разблокировки, поэтому для выпущенной игры заранее проверьте миграцию существующих сохранений. Самый безопасный вариант — добавлять новую карточку в конец массива.

## Этап 2. Подготовить уровни

Новая локация не может быть пустой: генератор требует хотя бы один `levelId`.

Создайте `levels/maps/<location-id>.xsb` и добавьте туда карты по правилам из документа [«Добавить уровень в существующую карточку»](add-level-to-existing-card.md#этап-2-добавить-карту-в-xsb). Также создайте пустой `levels/appearance/<location-id>.json`.

Если используются уже существующие карты, сначала удалите их `id` из прежней карточки. Один уровень нельзя назначить двум локациям.

## Этап 3. Добавить оформление и звук

Для уникального оформления добавьте исходники:

| Ресурс    | Путь                                                   | Значение в `locations.json`    |
| --------- | ------------------------------------------------------ | ------------------------------ |
| карточка  | `raw-assets/levels{copy}/level-cards/card-harbor.webp` | `"cardTexture": "card-harbor"` |
| фон       | `raw-assets/levels{copy}/backgrounds/harbor.webp`      | `"background": "harbor"`       |
| окружение | `raw-assets/audio/ambience/amb_harbor.mp3`             | `"ambience": "amb_harbor"`     |
| музыка    | `raw-assets/audio/music/level-music/m_harbor.mp3`      | `"music": "m_harbor"`          |

Можно повторно использовать существующие ресурсы: в таком случае новые файлы не нужны, достаточно указать существующие имена.

Имена чувствительны к точному совпадению. Фон и аудио загружаются по пути, построенному из значения конфигурации; неправильное имя проявится ошибкой загрузки во время игры.

## Этап 4. Добавить локализацию

В `raw-assets/gameConfig{copy}/locales/locales.json` добавьте один и тот же ключ во все поддерживаемые языки:

```json
{
  "locations.harbor": "Гавань"
}
```

```json
{
  "locations.harbor": "Harbor"
}
```

Соблюдайте существующую структуру языковых секций файла. В `titleKey` записывается ключ, а не готовый отображаемый текст.

## Этап 5. Создать объект локации

Добавьте объект в нужную позицию массива `locations` в `levels/locations.json`:

```json
{
  "id": "harbor-1",
  "titleKey": "locations.harbor",
  "cardTexture": "card-harbor",
  "background": "harbor",
  "ambience": "amb_harbor",
  "music": "m_harbor",
  "levelIds": ["sokoban-102", "sokoban-103"]
}
```

Проверьте:

1. `id` локации уникален и не будет меняться после релиза;
2. `titleKey` присутствует во всех языках;
3. каждый `levelId` существует в XSB новой локации;
4. каждый уровень назначен только одной локации;
5. порядок объекта в `locations` соответствует требуемому номеру главы;
6. порядок `levelIds` соответствует номерам уровней внутри карточки.

## Этап 6. Учесть лимит вкладок глав

Сейчас в игре 16 карточек и четыре жёстко созданные вкладки по четыре карточки. Это означает:

- замену существующей карточки можно выполнить без изменения количества вкладок;
- вставка карточки в позиции 1–16 перераспределит последующие карточки между существующими вкладками;
- 17-я и последующие карточки не получат доступной вкладки без изменения UI.

Если новая карточка увеличивает количество локаций больше 16, потребуется отдельная доработка:

1. в `src/game/states/stateGame/startScreen/locationSelect/LocationSelectView.js` создавать количество вкладок по `Math.ceil(locations.length / PAGE_SIZE)`, а не фиксированный массив из четырёх элементов;
2. передавать актуальное количество локаций до создания или обновления вкладок;
3. проверить расположение пяти и более вкладок в широком и узком интерфейсе;
4. убедиться, что `LevelProgress` ограничивает `locationPageIndex` новым количеством страниц;
5. проверить подписи диапазонов: «Главы 17–20» и неполный последний диапазон;
6. проверить переход к новой странице после разблокировки карточки.

Это изменение относится к UI и прогрессу, а не к `locations.json`. Сам JSON уже поддерживает произвольное количество объектов.

## Этап 7. Пересобрать конфигурацию и ассеты

Запустите:

```bash
npm run levels
npm run assets
npm run levels:check
```

Команды создадут игровой каталог, обработают новые ресурсы и проверят актуальность результата. `npm start` и `npm run build` также выполняют необходимую предварительную генерацию автоматически.

Не редактируйте вручную:

- `src/game/gameConfig/levels/generated/<location-id>.json`;
- `public/assets`;
- `.assetpack`.

Это сгенерированные данные.

## Этап 8. Проверить иерархию в игре

Проверьте новый профиль игрока и существующее сохранение.

Для нового профиля:

1. карточка находится в правильной вкладке и позиции;
2. отображаются название и изображение;
3. карточка заблокирована, пока не пройдена предыдущая;
4. после прохождения предыдущей карточки новая разблокируется;
5. анимация разблокировки на экране победы и главном экране работает;
6. внутри карточки отображаются все назначенные уровни;
7. фон, ambience и музыка загружаются;
8. после прохождения всех уровней открывается следующая карточка.

Для существующего сохранения:

1. ранее пройденные уровни остаются пройденными;
2. сохранённые `selectedLocationId`, `unlockedLocationIds` и `celebratedLocationIds` не ссылаются на удалённые идентификаторы;
3. кнопка «Продолжить» выбирает ожидаемую карту;
4. вставка карточки в середину не открывает и не блокирует главы неожиданным образом.

## Готово, когда

- локация занимает правильную позицию в `locations`;
- все её уровни существуют и не назначены другим карточкам;
- локализация присутствует во всех языках;
- карточка, фон и аудио успешно загружаются;
- цепочка разблокировки проверена на новом и существующем сохранении;
- для карточек после 16-й расширен и проверен UI вкладок;
- `npm run levels:check`, `npm run typecheck` и `npm run build` проходят.
