# Уровни Sokoban: устройство, XSB и проверка

## Коротко

Исходные карты разделены по фиксированной сложности:

```text
levels/library/custom/easy/custom-001.xsb
levels/library/XSokoban/medium/xSokoban-004.xsb
levels/library/XSokoban/hard/xSokoban-022.xsb
levels/library/XSokoban/very-hard/xSokoban-010.xsb
...
```

Сейчас в этих файлах 101 карта. Один файл содержит одну карту, имя файла совпадает с её постоянным `id`, а папка задаёт сложность. Распределение по локациям и порядок кнопок задаются независимо в `levels/locations.json`.

Для проверки в JSoko открывайте XSB выбранного уровня. Редактировать сгенерированные JSON или вручную переводить символы во внутренний формат игры не требуется.

## Какие файлы за что отвечают

| Файл                                            | Назначение                                                  | Можно редактировать            |
| ----------------------------------------------- | ----------------------------------------------------------- | ------------------------------ |
| `levels/library/<source>/<difficulty>/<id>.xsb` | Геометрия, происхождение и ручная сложность карты           | Да                             |
| `levels/library/<source>/author.json`           | Служебный идентификатор автора группы                       | При добавлении источника       |
| `levels/appearance/<location-id>.json`          | Варианты текстур стен, пола и ящиков                        | Да                             |
| `levels/locations.json`                         | Порядок локаций, их оформление и распределение карт по `id` | Да                             |
| `tools/sokoban-levels/build.mjs`                | Проверяет XSB и создаёт игровой конфиг                      | Обычно нет                     |
| `src/game/generatedAssets/levels/*`        | Сгенерированные игровые JSON по локациям                    | Нет                            |
| `levels/SOURCES.md`                             | История происхождения и проверки карт                       | При добавлении внешних наборов |

Главное правило: родительская группа задаёт автора, папка сложности — категорию, XSB-файл — геометрию, а массивы `levelIds` в `levels/locations.json` — состав и порядок локаций.

## Локации и карточки

Игра показывает 16 последовательных локаций по четыре карточки на вкладке. Сейчас 101 уровень распределён без повторений: первые пять локаций содержат по 7 карт, остальные — по 6.

В интерфейсе каждая локация является отдельной главой, а вкладки только группируют главы по четыре. Отдельного массива глав нет: позиции 1–4 массива `locations` образуют вкладку «Главы 1–4», позиции 5–8 — «Главы 5–8» и так далее. Порядок объектов одновременно определяет номер главы и последовательность разблокировки.

У каждой локации в `levels/locations.json` есть:

- постоянный `id`, который используется в сохранениях;
- ключ локализованного названия `titleKey`;
- изображение карточки `cardTexture`;
- фон уровня `background`;
- звук окружения `ambience` и музыка `music`;
- массив `levelIds` в порядке прохождения.

Фон и звук больше не дублируются у каждого уровня. Чтобы заменить оформление целой главы, достаточно изменить одну запись локации. Исходники карточек лежат в `raw-assets/levels{copy}/level-cards`, фоны — в `raw-assets/levels{copy}/backgrounds`.

Следующая локация открывается после прохождения всех карт предыдущей. Внутри уже открытой локации все уровни доступны сразу: игрок может выбирать их в любом порядке и повторно запускать пройденные. Замки отображаются только на карточках локаций.

Сохранение использует постоянные идентификаторы уровней и локаций; старый числовой `levelIndex` автоматически переносится в новый формат при первом запуске.

Главная кнопка «Продолжить» показывает название локации и номер карты. Пока в текущей локации остаются непройденные карты, она возвращает к последнему реально запущенному уровню. После полного прохождения локации кнопка переключается на первую карту следующей открытой локации. Простое переключение предпросмотра не меняет эту точку продолжения.

После прохождения последней карты локации экран победы сразу показывает карточку следующей локации: карточка появляется сверху, замок падает и срывается вниз, выводится сообщение и непрерывно идёт конфетти. При первом возвращении на главный экран новая карточка также подсвечивается. Уже показанные на главном экране разблокировки сохраняются в `celebratedLocationIds`, поэтому после перезапуска игры это празднование не повторяется.

В админ-панели уровни выбираются в два шага: сначала локация, затем карта внутри неё. Сохранение такого выбора считается явным отладочным переходом, поэтому панель открывает выбранную локацию вместе со всеми предшествующими и делает выбранную карту точкой «Продолжить».

## Что такое XSB

XSB — текстовый формат обмена уровнями Sokoban. Его понимают редакторы, игры и автоматические решатели.

| Символ | Значение                  |
| ------ | ------------------------- |
| `#`    | стена                     |
| пробел | свободный пол             |
| `@`    | игрок                     |
| `$`    | ящик                      |
| `.`    | цель                      |
| `*`    | ящик, уже стоящий на цели |
| `+`    | игрок, стоящий на цели    |

Пример уровня:

```text
; id: custom-012
######
#    #
# .$ #
#  @ #
######
```

Строка `; id: ...` является комментарием с постоянным идентификатором карты. Карты разделяются одной пустой строкой.

## Требования к карте

Генератор проверяет следующие условия:

- присутствует ровно один игрок: `@` или `+`;
- присутствует хотя бы один ящик;
- количество ящиков совпадает с количеством целей;
- используются только стандартные символы XSB;
- ширина не превышает 20 клеток;
- высота не превышает 20 клеток;
- идентификатор уровня не повторяется;
- строки корректно преобразуются во внутренний прямоугольный формат игры.

Стены желательно делать замкнутыми. Открытый проход во внешнюю пустоту может привести к тому, что генератор воспримет часть пола как пространство за пределами уровня.

Не используйте табуляцию. Открывайте файл моноширинным шрифтом и не удаляйте ведущие пробелы: они задают форму карты.

## Внутренний формат игры

В XSB всегда используются стандартные символы. Генератор сам выполняет перевод:

| XSB                 | Внутри игры |
| ------------------- | ----------- |
| внешний пробел      | `_`         |
| `*` — ящик на цели  | `-`         |
| `+` — игрок на цели | `*`         |

Символы `_` и `-` вручную в `levels/library/**/*.xsb` добавлять нельзя. Они относятся только к сгенерированным игровым JSON.

## Дорожные карты расширения игры

Пошаговые сценарии вынесены в отдельный раздел документации:

- [добавить уровень в существующую карточку](add-level-to-existing-card.md);

Первая дорожная карта охватывает привязку к `levelIds`, генерацию и игровую проверку. Вторая описывает ресурсы, локализацию, позицию в иерархии, цепочку разблокировки и ограничение текущего интерфейса четырьмя вкладками по четыре карточки.

## Как изменить существующий уровень

1. Найдите карту по имени файла или строке `; id: ...`.
2. Не меняйте `id`, если карта остаётся тем же уровнем.
3. Измените геометрию в `levels/library/<source>/<difficulty>/<level-id>.xsb` или визуальном редакторе.
4. Запустите `npm run levels`.
5. Проверьте изменённую карту кнопкой «Проверить» в редакторе или пройдите её вручную.

Для экспериментов в JSoko используйте копию: программа может переформатировать комментарии и пробелы рабочего файла.

## Что делает генератор

Команда `npm run levels`:

1. обнаруживает группы авторов и читает карты из `levels/library/<source>/<difficulty>/*.xsb`;
2. проверяет символы, размеры, игрока, ящики и цели;
3. проверяет уникальность `id`;
4. преобразует стандартный XSB во внутренние символы игры;
5. проверяет, что назначенные карты существуют и не повторяются между локациями; неназначенные карты остаются в библиотеке;
6. создаёт отдельные JSON в `src/game/generatedAssets/levels`;
7. назначает последовательные имена `level0`, `level1` и далее;
8. добавляет оформление, окружение и музыку из конфигурации локации.

Команда `npm run levels:check` ничего не перезаписывает. Она завершается ошибкой, если игровой JSON устарел или данные уровней некорректны.

`npm start` и `npm run build` сначала автоматически выполняют `npm run levels`.

Результаты решателей не хранятся в каталоге уровней и не участвуют в сборке. Сложность задаётся только расположением XSB-файла.

## Категории сложности

Сложность назначается вручную и не пересчитывается при изменении стен, декора, статистики решателя или позиции уровня в локации:

- `easy` — лёгкий;
- `medium` — средний;
- `hard` — тяжёлый;
- `very-hard` — очень тяжёлый.

Чтобы изменить категорию, переместите XSB-файл в другую папку. Чтобы изменить карточку или порядок кнопок слева направо, переставьте `id` в `levels/locations.json`. Эти две операции независимы.

## Авторы и происхождение

Каждая непосредственная подпапка `levels/library` является отдельной группой происхождения и содержит `author.json`:

```json
{
  "authorId": "exampleAuthor"
}
```

`authorId` — стабильный идентификатор автора в camelCase и одновременно подпись для отладочного интерфейса. Список авторов в коде отсутствует: чтобы добавить источник, создайте новую группу и подпапки `easy`, `medium`, `hard`, `very-hard`. Изменённый импортированный уровень остаётся у исходного автора; в `custom` помещаются только карты, полностью созданные с нуля.

Идентификаторы карт нумеруются независимо внутри каждого источника: `custom-001`, `custom-002` и `xSokoban-001`, `xSokoban-002`. Существующие ID не перенумеровываются после добавления или удаления карт; порядок показа задаётся только массивами `levelIds`.

## Рекомендуемый решатель: JSoko

JSoko — бесплатная программа с графическим интерфейсом для Windows, macOS и Linux. Она открывает XSB-файлы, умеет решать одну карту, диапазон или всю коллекцию.

Официальный сайт: <https://jsokoapplet.sourceforge.io/index.php>

Инструкция решателя: <https://jsokoapplet.sourceforge.io/help/help/solver.html>

### Проверка всех уровней

1. Установите Windows x64-версию JSoko.
2. Выберите `Level → Load external level`.
3. Откройте XSB нужного уровня из соответствующей группы в `levels/library`.
4. Убедитесь, что программа корректно показала карту.
5. Выберите `Solver → Open solver`.
6. Выберите метод `Any solution`.
7. В разделе уровней выберите `Whole collection`.
8. Установите лимит 60–300 секунд на одну карту.
9. Включите `Display solutions` и сохранение solver log.
10. Запустите проверку.

Для одного рабочего файла выберите `Only current level`. Если проверяете временную коллекцию, задайте нужный диапазон карт.

Для пакетной проверки нескольких уровней можно временно собрать их копии в отдельную XSB-коллекцию. Рабочие файлы библиотеки при этом не изменяйте.

`Any solution` — правильный режим для проверки проходимости. Режим `Push optimal` пытается доказать минимум толчков и обычно требует намного больше времени и памяти.

### Как понимать результат

- `Solved` и сохранённая последовательность ходов доказывают, что карта проходима.
- `Timeout` означает только истечение лимита. Это не доказательство непроходимости.
- ошибка чтения обычно означает посторонний символ, табуляцию или повреждённое разделение карт;
- если программа не понимает комментарии `; id: ...`, сделайте временную копию и удалите из неё только строки, начинающиеся с `;`.

Неудача одного решателя не доказывает, что решения нет. Сложную карту стоит повторить с большим лимитом или проверить другим решателем.

## Takaken для пакетной проверки

Takaken удобен для автоматического запуска из командной строки Windows. Официальная версия 7.4 принимает многоуровневый файл, лимит времени и диапазон уровней:

<https://computerpuzzle.net/english/sokoban/ver740/index.html>

Пример:

```powershell
takaken74.exe -in "D:\path\to\levels\library\XSokoban\hard\xSokoban-022.xsb" -out "D:\path\to\results.txt" -time 300 -level 1
```

Для первого знакомства проще JSoko: там видны карта, прогресс, найденные решения и уровни, завершившиеся по тайм-ауту.

## Личный рекорд

Игра хранит личный рекорд пользователя по числу толчков. Он обновляется только после прохождения уровня с меньшим результатом; обычные шаги по свободному полу на него не влияют. Пока уровень не пройден, интерфейс показывает прочерк.

## Частые ошибки

### Уровень есть в XSB, но не появился в игре

Добавьте его постоянный `id` в `levelIds` нужной локации. Генератор также завершится ошибкой, если карта не назначена никуда или назначена дважды.

### `Unsupported symbol` или `Недопустимая строка`

В карте присутствуют `_`, `-`, табуляция или другой нестандартный символ. Используйте только `#`, пробел, `@`, `$`, `.`, `*`, `+`.

### Число ящиков и целей не совпадает

Учитывайте комбинированные символы: `*` одновременно является ящиком и целью, `+` — игроком и целью.

### Карта превышает 20×20

Уменьшите поле или отдельно измените ограничения и проверьте адаптивное отображение в игре.

### Решатель долго работает

Используйте `Any solution`, увеличивайте лимит постепенно и сначала проверяйте одну карту. Поиск оптимального решения может быть на порядки сложнее поиска любого прохождения.

## Контрольный список перед коммитом

- каждая карта находится в отдельном XSB внутри одной папки `levels/library/<source>/<difficulty>`;
- у каждой карты есть уникальный `; id:`;
- каждый включённый в игру `id` ровно один раз указан в `levels/locations.json`; остальные карты остаются в запасе;
- `npm run levels` проходит;
- `npm run levels:check` проходит;
- изменённые карты решены хотя бы одним решателем;
- уровень проверен визуально в ландшафтном режиме;
- `npm run typecheck` и `npm run build` проходят.
