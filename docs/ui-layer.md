# UiLayer

`UiLayer` — корневой контейнер всего игрового интерфейса. Он отделён от отображения игрового мира, пересчитывает доступную UI-область и делит интерфейс по времени жизни. Расчёты позиции и масштаба адаптивных элементов делегируются [`AdaptiveLayout`](../src/game/engine/uiLayer/AdaptiveLayout.ts).

Основной файл: [`UiLayer.ts`](../src/game/engine/uiLayer/UiLayer.ts).

## Структура

```text
UiLayer
├─ globalUiLayer
├─ stateUiLayer
└─ modalLayer
   ├─ modalFade
   └─ activeModal
```

`UiLayer` использует `sortableChildren`, поэтому порядок верхних веток определяется через `zIndex`:

- `stateUiLayer` — интерфейс активного стейта;
- `globalUiLayer` с `zIndex: 1` — постоянный интерфейс над элементами стейта;
- `modalLayer` с `zIndex: 10` — fade и активная модалка поверх всего UI.

Не добавляйте прикладные элементы непосредственно в `UiLayer`. Его корневые дочерние элементы — только инфраструктурные слои.

## Как выбрать слой

| Слой | Что в нём хранить | Кто очищает |
| --- | --- | --- |
| `globalUiLayer` | Шестерёнка, отладочная панель и другой UI, переживающий смену стейтов | Владелец элемента |
| `stateUiLayer` | Меню, HUD, подсказки и прочие элементы текущего стейта | `destroyStateUiLayerChildren()` при смене стейта |
| `modalLayer` | Только активную модалку и принадлежащий слою fade | `closeModal()` или `BaseModal.hide()` |

### Постоянный элемент

```js
const button = new Container({label: 'settingsButton'})
Locator.uiLayer.globalUiLayer.addChild(button)
```

Добавленный сюда объект не будет автоматически уничтожен при смене стейта. Его владелец обязан снять подписки и уничтожить объект, когда тот больше не нужен.

### Элемент текущего стейта

```js
const menu = new Container({label: 'startMenu'})
Locator.uiLayer.stateUiLayer.addChild(menu)
```

При переходе между основным экраном и уровнем стейты вызывают:

```js
Locator.uiLayer.destroyStateUiLayerChildren()
```

Метод удаляет и уничтожает всех прямых потомков `stateUiLayer` вместе с их дочерними элементами. Не храните в этом слое объекты, которые должны быть переиспользованы следующим стейтом.

## Resize

`GameResize` обновляет `GameContainer`, затем `UiLayer`, после этого активный стейт и в конце один раз отправляет `GAME_EVENTS.gameResize`.

Во время `UiLayer.resize()`:

1. Пересчитывается `uiData`.
2. `boundsArea` обновляется до полного размера видимой UI-области.
3. Обновляется положение самого `UiLayer`.
4. Прямые потомки `globalUiLayer` и `stateUiLayer`, а также активная модалка передаются в `AdaptiveLayout` через `resizeAdaptive()`.
5. Обновляются debug-рамка и оба вида fade.

Явная `boundsArea` не зависит от состава дочерних элементов. Поэтому `getBounds()` всегда возвращает границы всего UI, даже если debug-рамка отключена или текущий стейт не заполняет экран элементами.

Вложенные элементы рекурсивно не обходятся. Если адаптивный объект вложен в другой контейнер, адаптивным должен быть его верхний родитель либо родитель должен самостоятельно раскладывать содержимое.

Новый элемент, созданный после последнего resize, должен сразу выполнить своё первоначальное позиционирование. Подробности находятся в [документации по адаптивности](adaptive-ui.md).

## Правила использования

- У каждого `Container` и производного Pixi-элемента должен быть понятный уникальный `label`.
- Постоянный UI добавляется только в `globalUiLayer`.
- UI стейта добавляется только в `stateUiLayer`.
- Модалки открываются через модальный API, а не через `addChild()`.
- Не меняйте `zIndex` верхних слоёв ради отдельного окна — для него уже существует `modalLayer`.
- Не вызывайте `destroyStateUiLayerChildren()` из отдельных компонентов: это операция жизненного цикла стейта.
